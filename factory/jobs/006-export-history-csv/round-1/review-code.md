## Non-blocking notes

- **The web branch has no automated test.** That is not blocking here: the spec's test bullet and test plan pin the mobile path (mock `MOBILE: true`) and the empty-log state, and the web path is intentionally the same as `Settings.doExport`; the real web click is evidenced by `factory-006-history-360-dark-exported.png` and I independently reproduced its 1001-byte payload. If you want the `Could not export the history` branch pinned later, it would need a `MOBILE: false` case with `URL.createObjectURL` throwing (plus a stub for the anchor click).
- **Unknown-start ordering is a documented judgement call, not a pinned test.** `history-csv.js:61-64` puts a workout with no parseable `start` after the known starts on the same date, with the stored index deciding among unknowns. The spec only says "then start" and does not define a missing value; the choice is deterministic and does not affect rows that have starts. A small test would make it explicit if the team wants it locked.
- **The screen test does not prove the export ignores the search field.** It seeds one workout and never types a query, so a future regression that exported the filtered list instead of `S.workouts` would still pass. The implementation reads `S.workouts` directly (`History.jsx:57`), which matches the spec's "whole log regardless of search", so this is a test-completeness note rather than a defect.
- Minor, unspecified: `toCSV` returns `''` for a non-array `rows` rather than throwing, and the test's full-payload equality reuses `toCSV`/`historyRows` (self-consistent rather than independent); the dedicated lib suites are the independent pins for both.
